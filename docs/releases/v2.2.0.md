# Familiar v2.2.0

[中文](#中文) | [English](#english)

## 中文

### 主要功能与修复

- 重构 macOS 桌宠鼠标穿透：左键可操作后方窗口，开启穿透时仍可通过右键打开桌宠菜单，并可直接在菜单中切换穿透状态。
- 新增悬停透明度、屏幕边缘吸附和拖拽可见区域约束；桌宠位置按显示器工作区比例保存，在分辨率、显示器或内容尺寸变化后保持稳定。
- 加固右键菜单布局：靠近屏幕边缘时自动扩展透明窗口并限制在工作区内，空闲 5 秒后自动关闭。
- 新增本地与远程两种首次启动引导路径，改进连接反馈、输入焦点和 Hook 设置状态展示。
- 更新中英文 README 与官网，展示不同编码 Agent 驱动桌宠状态变化的工作方式。
- 新增 `scripts/install-macos.sh`，支持从 `origin/main` 更新安装，或使用 `--local` 构建、安装并启动当前工作区版本。

### 兼容性与配置迁移

- 新增 `renderer.desktop-pet.hover_opacity`，旧配置缺失时默认使用 `0.35`。
- 新增 `renderer.desktop-pet.snap_to_corner` 与 `snap_threshold`，旧配置缺失时分别默认使用 `true` 和 `60.0`。
- 桌宠拖拽位置会逐步保存为 `rel:rx,ry`；原有命名锚点和绝对像素位置仍可读取，无需手动迁移。
- macOS 桌宠新增 `block` 依赖；Windows 和 Linux 保留原有鼠标事件处理路径。
- 未改变 Hook 协议、远程订阅协议或默认本地运行模式。

### 隐私影响

- 不新增遥测、远程上报或用户数据采集。
- 鼠标位置检测、窗口吸附、位置保存和右键菜单处理均在本地完成，不会发送指针位置、窗口内容、提示词或 Hook 数据。
- 官网素材与引导页更新不改变运行时网络行为。

### 支持的平台与架构

- macOS Apple Silicon（arm64）与 Intel（x86_64）桌面包。
- Linux x86_64 deb 与 AppImage；桌面运行需要发行版提供 Tauri/WebKitGTK 依赖。
- Windows x86_64 NSIS 安装包；Windows 本地 Hook 使用 loopback TCP。
- `familiar-cli serve` 可在上述平台运行。

### 签名与公证状态

- macOS 使用 CI 配置的 ad-hoc 签名标识，不提供 Apple Developer ID 签名或公证；Gatekeeper 可能要求首次手动允许。
- Windows 安装包未配置代码签名；SmartScreen 可能要求首次安装手动确认。
- Linux deb/AppImage 未由发行版渠道签名。

### 性能数据

本版本未建立新的可复现端到端性能基线，不宣称量化性能变化。

## English

### Major features and fixes

- Reworked macOS desktop-pet click-through so left clicks reach windows behind the pet while right-click still opens the pet menu; click-through can also be toggled directly from that menu.
- Added hover opacity, screen-edge snapping, and visible-work-area drag constraints. Pet positions are persisted relative to the monitor work area so they remain stable across resolution, monitor, and content-size changes.
- Hardened context-menu layout by expanding the transparent window near screen edges, clamping the menu to the work area, and closing it after five idle seconds.
- Added separate local and remote onboarding paths with clearer connection feedback, input focus, and Hook setup status.
- Refreshed the English and Chinese READMEs and website to demonstrate how different coding agents drive pet states.
- Added `scripts/install-macos.sh` for updating from `origin/main`, or building, installing, and launching the current workspace with `--local`.

### Compatibility and configuration migration

- Added `renderer.desktop-pet.hover_opacity`, defaulting to `0.35` when absent from older configurations.
- Added `renderer.desktop-pet.snap_to_corner` and `snap_threshold`, defaulting to `true` and `60.0` respectively when absent.
- Dragged pet positions are progressively stored as `rel:rx,ry`; existing named anchors and absolute pixel positions remain readable, so no manual migration is required.
- The macOS desktop app adds the `block` dependency; Windows and Linux retain their existing mouse-event paths.
- Hook protocols, the remote subscription protocol, and the default local runtime mode are unchanged.

### Privacy impact

- No telemetry, remote reporting, or user-data collection is added.
- Pointer detection, window snapping, position persistence, and context-menu handling run locally and do not transmit pointer positions, window contents, prompts, or Hook payloads.
- Website assets and onboarding updates do not change runtime network behavior.

### Supported platforms and architectures

- macOS desktop bundles for Apple Silicon (arm64) and Intel (x86_64).
- Linux x86_64 deb and AppImage packages; the desktop requires the distribution's Tauri/WebKitGTK dependencies.
- Windows x86_64 NSIS installer; Windows local Hook ingest uses loopback TCP.
- `familiar-cli serve` can run on the platforms above.

### Signing and notarization status

- macOS uses the ad-hoc signing identity configured in CI and is not signed with an Apple Developer ID or notarized; Gatekeeper may require manual approval on first launch.
- The Windows installer is not code-signed; SmartScreen may require manual confirmation on first install.
- Linux deb/AppImage artifacts are not signed by a distribution channel.

### Performance data

No new reproducible end-to-end performance baseline was established for this release, and no quantified performance change is claimed.
