# Familiar v1.0.0

[中文](#中文) | [English](#english)

## 中文

### 主要更新

Familiar 发布首个正式版本（1.0.0）。自 v0.5.4 以来新增以下能力：

- **内置更新**：基于 GitHub Releases 实现更新检查。支持设置面板手动检查与应用启动时自动检查（受新增 `[update]` 配置段控制，间隔支持每天/每周）；检测到新版本时弹窗提醒，显示版本号、发布日期与更新说明；可选择「去下载」（打开浏览器下载安装包）、「跳过此版本」（该版本不再提醒，出现更新版本后再提醒）或「永久忽略」。托盘菜单新增「检查更新」入口。更新检查仅向 GitHub API 查询最新版本信息，不自动下载或安装。
- **官网页面**：为项目创建纯静态双语官网（中文默认、英文一键切换），托管到 GitHub Pages，包含特性、集成支持、性能数据、隐私与下载入口；新增 GitHub Actions 部署工作流。

本版本同时达到稳定定位：核心事件流水线、Hook 集成（Claude Code / Codex CLI / Qoder / Google Antigravity）、数据清理模块与上述新能力共同构成首个可对外发布的正式版。

### 配置兼容性

- 新增 `[update]` 配置段（`check_on_startup` / `interval` / `skipped_version` / `ignored_versions` / `last_check_at`）。旧配置文件不包含该段时按默认值加载（默认启动自动检查、每天一次），无需手工迁移。
- 既有配置（`[cleanup]`、`event_status_map` 等）继续原样生效。
- 版本号来源统一：设置面板「关于」中的版本号改为从应用运行时获取，不再硬编码。

### 隐私

- 本版本新增首次出站网络请求：更新检查会向 `api.github.com` 查询 `releases/latest` 的版本信息。请求仅包含标准 User-Agent，不发送任何本地数据、提示词、命令、路径或 Hook 载荷，也不包含遥测。
- 其余所有数据继续仅在本机采集、处理和显示；未新增其它远程服务。

### 平台与制品

- 本次 Release 计划提供以下安装包（draft 阶段，构建完成后上传）：
  - macOS Apple Silicon（arm64）DMG。
  - macOS Intel（x64）DMG。
  - Windows x86_64 NSIS 安装包。
  - Linux x86_64 deb 与 AppImage。
- 每个平台制品对应的 SHA-256 校验和见 Release 附件的 `SHA256SUMS`。
- macOS 应用仅使用 ad-hoc 签名，未进行 Apple Developer ID 签名或公证。首次启动时 Gatekeeper 可能要求用户手动允许。
- Windows 安装包未做代码签名，SmartScreen 可能要求用户手动确认首次安装。
- Linux 安装包未经分发渠道签名。

### 性能数据

本轮新增内置更新（一次性的启动/手动 HTTP 检查，受间隔门控）与官网页面，无持续运行时性能变化。既有采样数据（Apple Silicon macOS、30 秒空闲采样）保持不变：平均 CPU 0.013%、物理内存约 37 MiB。

## English

### Highlights

Familiar reaches its first stable release (1.0.0). New since v0.5.4:

- **In-app updates**: update checking based on GitHub Releases. Manual checks from the settings panel plus an optional startup auto-check (gated by the new `[update]` config section, daily or weekly interval). When a newer release exists a modal shows the version, release date, and release notes with actions to **Download** (opens the installer page in the browser), **Skip this version** (suppressed until a newer release appears), or **Ignore permanently**. A tray "Check for Updates" item is also added. The check only queries the latest version from the GitHub API; nothing is auto-downloaded or installed.
- **Official website**: a static, bilingual landing page (Chinese default with a one-click English toggle) hosted on GitHub Pages, covering features, supported integrations, performance, privacy, and download links; a GitHub Actions deployment workflow is included.

This release also marks the project's stability milestone: the core event pipeline, hook integrations (Claude Code / Codex CLI / Qoder / Google Antigravity), the data-cleanup module, and the capabilities above together form the first generally released stable version.

### Configuration compatibility

- A new `[update]` section (`check_on_startup` / `interval` / `skipped_version` / `ignored_versions` / `last_check_at`) is added. Existing config files without the section load with defaults (auto-check on startup, daily) — no manual migration needed.
- Existing settings such as `[cleanup]` and `event_status_map` continue to work unchanged.
- The version shown in Settings → About is now sourced from the running application instead of a hardcoded string.

### Privacy

- This release introduces the first outbound network request: the update check queries `releases/latest` from `api.github.com`. The request carries only the standard User-Agent and sends no local data — no prompts, commands, paths, or hook payloads — and no telemetry.
- All other data continues to be collected, processed, and displayed locally only; no other remote service was added.

### Platforms and artifacts

- This Release plans to include the following installers (draft stage; will be uploaded once built):
  - macOS DMG for Apple Silicon (arm64).
  - macOS DMG for Intel (x64).
  - Windows x86_64 NSIS installer.
  - Linux x86_64 deb and AppImage.
- SHA-256 checksums for each platform artifact are available in the `SHA256SUMS` release asset.
- The macOS application is ad-hoc signed and is not signed with an Apple Developer ID or notarized. Gatekeeper may require manual approval on first launch.
- The Windows installer is not code-signed; SmartScreen may require manual confirmation on first install.
- The Linux packages are not signed by a distribution channel.

### Performance data

This round adds in-app update checking (a one-off HTTP check at startup or on demand, gated by the interval) and the website; no ongoing runtime performance change was introduced. Existing sampled data (Apple Silicon macOS, 30-second idle sample) is unchanged: ~0.013% average CPU and ~37 MiB physical memory footprint.
