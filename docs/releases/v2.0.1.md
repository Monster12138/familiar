# Familiar v2.0.1

[中文](#中文) | [English](#english)

## 中文

### 本版本修复

- 修复 macOS Intel（x86_64）桌面包构建失败的问题：调用 Cocoa `setFrame:display:` 时使用平台正确的 Objective-C `BOOL` 常量。
- 版本号统一升级至 `2.0.1`。

### 自 v2.0.0 起的主要更新

- **本地一体化与远程订阅双模式**：默认继续本地运行，也可以通过 `[runtime].mode = "remote"` 让桌面端只订阅远程服务端状态。
- **State Stream**：新增版本化 WebSocket 状态流，使用完整快照、latest-only 合并、初始快照、心跳、限频和断线重连。
- **职责分离**：Tauri 本地端与 `familiar-cli serve` 共用 Hook ingest、事件解析和状态模型。
- **服务端能力**：新增 `familiar-cli serve --config`、`--bind`，支持可配置 HTTP/HTTPS、状态摘要脱敏和优雅退出。
- **会话身份稳定性**：事件 ID 与会话 ID 解耦，非 UUID 的 Agent conversation ID 也能稳定聚合。
- **桌面端提示**：远程模式增加连接状态标识，并同步用户输入摘要、活动摘要、统计和来源信息。

### 兼容性与配置迁移

- 旧配置缺少 `[runtime]` 时仍默认为 `local`，无需迁移即可启动。
- `headless` CLI 子命令不再保留兼容别名；服务端统一使用 `familiar-cli serve`。
- Hook ingest 默认使用 `19527`，HTTP/WebSocket State Stream 默认使用 `19528`，避免端口职责冲突。
- 服务端可使用 `familiar-cli serve --config /path/server.toml`，Hook CLI 进程可通过 `FAMILIAR_CONFIG` 指定同一配置文件。
- 远程模式的 TLS、端点、重连和摘要长度配置位于 `[remote]`；服务端证书配置位于 `[server.tls]`。
- 本版本不改变配置格式、远程订阅协议或默认部署模式，无需额外迁移配置。

### 隐私影响

- 不新增遥测或默认外部上报。
- 原始 Hook payload、命令、文件内容和完整转录仍只在产生它们的服务端处理；State Stream 只发送版本化状态和经过长度限制的摘要。
- 远程模式下 Agent 统计来自服务端；CPU、内存和磁盘仪表仍读取本地桌面机器。
- TLS 和远程认证均由用户配置控制；本版本不包含设备身份、Token 轮换或凭证库集成。

### 平台与架构

- macOS Apple Silicon（arm64）与 Intel（x86_64）桌面包。
- Linux x86_64 deb 与 AppImage；桌面运行需要发行版提供 Tauri/WebKitGTK 依赖。
- Windows x86_64 NSIS 安装包；Windows 本地 Hook 仅使用 loopback TCP，不使用 Unix Domain Socket。
- `familiar-cli serve` 可在上述平台运行；TLS 构建仍应在目标平台 CI 上验证系统工具链和证书路径。

### 签名与公证状态

- macOS 使用 CI 配置的 ad-hoc 签名标识，不提供 Apple Developer ID 签名或公证；Gatekeeper 可能要求首次手动允许。
- Windows 安装包未配置代码签名；SmartScreen 可能要求首次安装手动确认。
- Linux deb/AppImage 未由发行版渠道签名。

### 性能数据

本版本主要为 macOS 构建兼容性修复，未建立新的可复现端到端性能基线，也不宣称量化性能变化。

## English

### Fixes in v2.0.1

- Fixed macOS Intel (x86_64) desktop bundle builds by passing Cocoa's platform-correct Objective-C `BOOL` constant to `setFrame:display:`.
- Unified the release version at `2.0.1`.

### Highlights since v2.0.0

- **Local integrated and remote subscription modes**: local mode remains the default, while `[runtime].mode = "remote"` lets the desktop shell subscribe to a remote server.
- **State Stream**: added a versioned WebSocket stream with complete snapshots, latest-only coalescing, an initial snapshot, heartbeat, rate limiting, and reconnect backoff.
- **Separated responsibilities**: the Tauri desktop and `familiar-cli serve` share Hook ingest, event parsing, and the state model.
- **Server operation**: added `familiar-cli serve --config` and `--bind`, configurable HTTP/HTTPS, sanitized state summaries, and graceful shutdown.
- **Stable session identity**: event IDs are separated from session IDs, so non-UUID Agent conversation IDs are still grouped consistently.
- **Desktop status**: remote mode shows connection status and synchronizes user-input summaries, activity summaries, statistics, and source counts.

### Compatibility and configuration migration

- Missing `[runtime]` in an older configuration still defaults to `local`; no migration is required.
- The `headless` CLI command no longer has a compatibility alias; use `familiar-cli serve` for the server.
- Hook ingest defaults to `19527`, while the HTTP/WebSocket State Stream defaults to `19528`.
- Use `familiar-cli serve --config /path/server.toml` for an explicit server configuration; set `FAMILIAR_CONFIG` for Hook CLI processes that must use the same file.
- Remote TLS, endpoint, reconnect, and summary limits are configured under `[remote]`; server certificates are configured under `[server.tls]`.
- This release does not change the configuration format, remote subscription protocol, or default deployment mode; no additional migration is required.

### Privacy impact

- No telemetry or default external reporting is added.
- Raw Hook payloads, commands, file contents, and full transcripts remain processed only on the service that receives them; the State Stream sends versioned state and length-limited summaries.
- Agent statistics in remote mode come from the server; CPU, memory, and disk gauges continue to describe the local desktop machine.
- TLS and remote authentication remain user-configurable; device identity, token rotation, and credential-store integration are not included.

### Platforms and architectures

- macOS desktop bundles for Apple Silicon (arm64) and Intel (x86_64).
- Linux x86_64 deb and AppImage packages; the desktop requires the distribution's Tauri/WebKitGTK dependencies.
- Windows x86_64 NSIS installer; Windows local Hook ingest uses loopback TCP and does not use Unix Domain Sockets.
- `familiar-cli serve` is intended to run on these platforms; TLS builds still require target-platform CI validation of the system toolchain and certificate paths.

### Signing and notarization status

- macOS uses the ad-hoc signing identity configured in CI and is not signed with an Apple Developer ID or notarized; Gatekeeper may require manual approval on first launch.
- The Windows installer is not code-signed; SmartScreen may require manual confirmation on first install.
- Linux deb/AppImage artifacts are not signed by a distribution channel.

### Performance data

This release is primarily a macOS build-compatibility fix. No new reproducible end-to-end performance baseline was established, and no quantified performance change is claimed.
