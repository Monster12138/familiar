# Familiar v0.5.3

[中文](#中文) | [English](#english)

## 中文

### 主要更新

- **可配置的事件 → 宠物状态映射**：设置面板新增「事件行为映射」，可将各 Agent 归一化后的每个事件类型（AgentStarted、Thinking、Processing、RunningCommand、TaskCompleted、TaskFailed、WaitingForInput 等）映射到指定的宠物状态（空闲 / 思考 / 工作 / 待处理 / 完成 / 失败），保存后立即生效，无需重启。未设置的事件沿用内置行为。
- **API 错误感知**：注册并解析 Claude Code 的 `StopFailure` hook（需 Claude Code ≥ v2.1.78），将限流、认证失败、计费、网络不通、超长输出等 API 错误识别为失败状态，宠物进入「警觉（Alarmed）」动画，而不是保持空闲。
- **状态重命名**：`WaitingInput` 状态更名为 `Pending`（配置值为 `waiting-input` → `pending`）；触发它的 `WaitingForInput` 事件名保持不变。
- **Hooks 面板增强**：Hooks 测试面板的表格新增「状态」列，直观显示每个 hook 事件最终产生的宠物状态（跟随用户在事件行为映射中的自定义）；移除冗长的测试命令文本列，保留「复制命令」按钮。
- **回归修复**：每轮对话（提示 → 回复）结束后宠物可靠地回到空闲状态，连续快速回合不再卡在庆祝动画。
- **发布流程修复**：修复 v0.5.2 中生成 `SHA256SUMS` 的 GitHub Actions 作业失败（`finalize-release` 作业的 `gh release` 命令缺少 `--repo`，导致无 git 环境时无法推断仓库）。

### 配置兼容性

- `event_status_map` 的取值中，`waiting-input` 更名为 `pending`。若存量配置写入了 `waiting-input`，会优雅回退到内置行为（不报错）；在设置面板重新选择一次即可写回新值。
- 其余配置不变，可直接沿用。

### 隐私

本版本没有新增遥测、远程数据上报或外部服务。所有数据继续仅在本机采集、处理和显示。

### 平台与制品

- 本次 Release 计划提供以下安装包（draft 阶段，构建完成后上传）：
  - macOS Apple Silicon（arm64）DMG。
  - macOS Intel（x64）DMG。
  - Windows x86_64 NSIS 安装包。
  - Linux x86_64 deb 与 AppImage。
- 每个平台制品对应的 SHA-256 校验和见 Release 附件的 `SHA256SUMS`。
- macOS 应用仅使用 ad-hoc 签名，未进行 Apple Developer ID 签名或公证。首次启动时 Gatekeeper 可能要求用户手动允许。
- Windows 安装包未做代码签名，SmartScreen 可能要求用户手动确认首次安装。
- Linux 安装包未经分发渠道签名。

### 性能数据

本轮无运行时性能变化；事件映射为启动/保存时读取的轻量查表，状态机每次事件仅做一次 O(1) 查找。

## English

### Highlights

- **Configurable event → pet-status mapping**: a new "Event Behaviors" settings section maps each normalized agent event type (AgentStarted, Thinking, Processing, RunningCommand, TaskCompleted, TaskFailed, WaitingForInput, ...) to a pet status (Idle / Thinking / Working / Pending / Completed / Failed). Changes apply immediately on save, no restart required; unmapped events keep the built-in behavior.
- **API-error awareness**: registers and parses Claude Code's `StopFailure` hook (Claude Code ≥ v2.1.78), turning rate limits, auth failures, billing errors, network issues, and max-output-length errors into a Failed status so the pet shows the "Alarmed" animation instead of staying idle.
- **Status rename**: the `WaitingInput` status was renamed to `Pending` (config value `waiting-input` → `pending`); the triggering `WaitingForInput` event name is unchanged.
- **Hooks panel enhancement**: the Hooks test panel now shows a "Status" column with the pet status each hook event resolves to (following your Event Behaviors customizations), removes the verbose test-command text column, and keeps a copy-command button.
- **Regression fix**: the pet reliably returns to idle after each conversation round; rapid successive rounds no longer leave it stuck in the celebrating animation.
- **Release-process fix**: fixes the GitHub Actions `SHA256SUMS` job failure in v0.5.2 (the `finalize-release` job's `gh release` commands lacked `--repo`, so the CLI could not infer the repository without a git checkout).

### Configuration compatibility

- In `event_status_map`, `waiting-input` was renamed to `pending`. Existing configs that set `waiting-input` fall back gracefully to the built-in behavior (no error); reselecting it in the settings panel writes back the new value.
- No other configuration changes; existing configurations continue to work as-is.

### Privacy

This release adds no telemetry, remote reporting, or external services. All data continues to be collected, processed, and displayed locally only.

### Platforms and artifacts

- This Release plans to include the following installers (draft stage; will be uploaded once built):
  - macOS DMG for Apple Silicon (arm64).
  - macOS DMG for Intel (x64).
  - Windows x86_64 NSIS installer.
  - Linux x86_64 deb and AppImage.
- SHA-256 checksums for each platform artifact are available in the `SHA256SUMS` release asset.
- The macOS application is ad-hoc signed and is not signed with an Apple Developer ID or notarized. Gatekeeper may require manual approval on first launch.
- The Windows installer is not code-signed; SmartScreen may require manual confirmation on first install.
- The Linux packages are not signed by a distribution channel.

### Performance data

No runtime performance changes this round; the event mapping is a small lookup table read at startup/save, and the state machine performs a single O(1) lookup per event.
