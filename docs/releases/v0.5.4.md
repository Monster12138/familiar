# Familiar v0.5.4

[中文](#中文) | [English](#english)

## 中文

### 主要更新

- **Qoder Hooks 与官方文档对齐**：注入的 hook 事件从 5 个扩展到 Qoder 官方支持的 12 个（`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PermissionRequest`、`PostToolUse`、`PostToolUseFailure`、`SubagentStart`、`SubagentStop`、`Stop`、`SessionEnd`、`PreCompact`、`Notification`）。工具类事件（`PreToolUse`、`PermissionRequest`、`PostToolUse`、`PostToolUseFailure`）补上官方 `matcher: "*"` 匹配全部工具；其余事件省略 matcher。
- **注入安全性修复**：对 Claude Code / Codex / Qoder / Antigravity 的注入操作增加保护——当已有配置文件不是合法 JSON 或不是 JSON 对象时，注入会中止并返回明确错误，不再回退为 `{}` 覆写整个配置文件（此前若配置文件格式损坏，familiar 会用自身 hooks 覆盖文件中的其它设置与 hooks，虽然会先做 `.bak` 备份）。
- **Codex 卸载标记收紧**：`is_injected()` 与卸载现在同时匹配注入命令中的 `--source codex` 标记，与 Claude Code / Qoder 的判定方式保持一致，避免误删用户手写、恰好调用 familiar-cli 的 hook。
- **Hook 集成规则文档化**：在 `AGENTS.md` 新增「Agent Hooks Integration」章节，固化后续新增其它 Agent hooks 支持时必须遵守的规范：与官方文档严格一致（注入全部官方事件）、保持被动观察者、注入合并式且解析失败即中止、卸载仅移除 familiar 自身的条目。

### 配置兼容性

- 无配置结构变更，`event_status_map` 等既有配置继续原样生效。
- 已注入过旧版 5 事件 Qoder hooks 的用户需重新执行一次「注入」以获取全部 12 个事件；重新注入为合并式，不会覆盖已有的其它 hook。

### 隐私

本版本没有新增遥测、远程数据上报或外部服务。所有数据继续仅在本机采集、处理和显示。

### 平台与制品

- 本次 Release 计划提供以下安装包（draft 阶段，构建完成后上传）：
  - macOS Apple Silicon（arm64）DMG。
  - macOS Intel（x64）DMG。
  - Windows x86_64 NSIS 安装包。
  - Linux x86_64 deb 与 AppImage。
- 每个平台制品对应的 SHA-256 校验和见 Release 附件的 `SHA256SUMS`。
- macOS 应用仅使用 ad-hoc 签名，未进行 Apple Developer ID 签名或公证。首次启动时 Gatekeeper 可能要求用户手动允许。
- Windows 安装包未做代码签名，SmartScreen 可能要求用户手动确认首次安装。
- Linux 安装包未经分发渠道签名。

### 性能数据

本轮为 hooks 集成与安全性修复，无运行时性能变化。

## English

### Highlights

- **Qoder hooks aligned with the official docs**: the injected hook set grows from 5 to all 12 officially supported events (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `SubagentStart`, `SubagentStop`, `Stop`, `SessionEnd`, `PreCompact`, `Notification`). Tool-scoped events (`PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`) carry the official `matcher: "*"` to match all tools; the others omit the matcher.
- **Injection safety fix**: injection for Claude Code / Codex / Qoder / Antigravity now aborts with a clear error when the existing config file is not valid JSON or not a JSON object, instead of falling back to `{}` and overwriting the whole file (previously a malformed config could be replaced by familiar's hooks, though a `.bak` backup was taken first).
- **Codex uninstall marker tightened**: `is_injected()` and uninstall now also match the `--source codex` marker in the injected command, consistent with the Claude Code / Qoder checks, so a hand-written hook that happens to call familiar-cli is no longer misidentified.
- **Hook integration rules documented**: a new "Agent Hooks Integration" section in `AGENTS.md` codifies the rules for adding hooks support for future agents: strict alignment with the official docs (inject every official event), stay a passive observer, merge-preserving injection that aborts on unparseable config, and surgical uninstall that removes only familiar's own entries.

### Configuration compatibility

- No configuration schema changes; existing settings such as `event_status_map` continue to work unchanged.
- Users who previously injected the older 5-event Qoder hook set should re-run the injection step to pick up all 12 events; re-injecting merges cleanly without overwriting other hooks.

### Privacy

This release adds no telemetry, remote reporting, or external services. All data continues to be collected, processed, and displayed locally only.

### Platforms and artifacts

- This Release plans to include the following installers (draft stage; will be uploaded once built):
  - macOS DMG for Apple Silicon (arm64).
  - macOS DMG for Intel (x64).
  - Windows x86_64 NSIS installer.
  - Linux x86_64 deb and AppImage.
- SHA-256 checksums for each platform artifact are available in the `SHA256SUMS` release asset.
- The macOS application is ad-hoc signed and is not signed with an Apple Developer ID or notarized. Gatekeeper may require manual approval on first launch.
- The Windows installer is not code-signed; SmartScreen may require manual confirmation on first install.
- The Linux packages are not signed by a distribution channel.

### Performance data

This round is a hooks-integration and safety fix; no runtime performance changes were introduced.
